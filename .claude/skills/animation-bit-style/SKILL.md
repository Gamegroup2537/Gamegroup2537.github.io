# Animation bit style

A recipe for knowledge clips that answer one question in about 30 seconds: a 3D subject is shown at real speed, time slows down, the outside is scanned away to reveal how it works inside, each part is explained in turn, and the clip returns to real speed with the answer and loops.

Everything is generated by code - picture, text and sound - so a clip is a small project folder, not a video file being edited. The bundled template is a finished, working clip ("which exercises give round shoulders?", Thai text). A new clip starts as a copy of it.

## What you are making

- 1080x1920, 30 fps, 32 s (16 bars at 120 BPM), seamless loop, H.264 + AAC
- One continuous shot; the camera moves, it never cuts
- No voice-over: captions carry the story, so the clip works muted
- One timeline drives everything. Picture, panels and sound all read the same data, which is why a bar on the chart moves exactly when the muscle does

## Workflow

### 1. Get the brief before touching code

A clip stands or falls on its script, and facts cannot be fixed in render. Read `references/brief.md` and collect what it lists. If the user gives only a topic, draft the brief yourself, show it to them as a short table (time / what happens / on-screen text) and get a yes before building. Check every factual claim; say so plainly when a claim is a simplification.

### 2. Decide what the subject costs

The expensive part of a new clip is the 3D subject, not the text.

| The topic is about... | Subject work |
|---|---|
| The same body and the same highlighted muscle (shoulders) | None - change text, poses, camera |
| The body, another muscle group | Moderate - add that muscle as the highlighted region, new poses |
| Something else (an engine, a joint, an organ, a device) | Large - model it from scratch; expect several rounds of stills |

Tell the user which row they are in before starting, because it sets how many review rounds to expect. `references/modeling.md` explains how subjects are built.

### 3. Scaffold

```bash
node <this-skill>/scripts/new-clip.mjs <project-folder>
cd <project-folder> && npm install
```

Then edit in this order, checking stills after each: timeline text and timing -> poses and camera -> subject -> panels -> sound events. `references/architecture.md` maps every file and data structure.

### 4. Review with stills, never with full renders

`node tools/render.mjs preview <frame numbers>` writes PNGs in about a minute. Send the user stills (frame = seconds x 30) and iterate on those. Render the whole clip only when the stills are approved.

This matters because without a graphics card a full render takes around 50 minutes; an early version of this workflow re-rendered after every small fix and wasted hours. On a machine with a graphics card the full build takes under a minute, which changes the advice - see step 5.

When a change is about proportion between two layers (skin vs. what is under it), render both layers in the same pose and overlay them: `QUERY="xray=0"` and `QUERY="xray=1"` pin the layer. Judging proportion from one layer alone is how mismatches slip through.

### 5. Render

Ask early whether the user has a computer with a graphics card.

- **They do:** the clip is built on their machine. Push the project, and give them one complete command line that starts with `cd` into the project folder - people paste it into a freshly opened terminal. On Windows PowerShell use `npm.cmd`, not `npm` (script execution is blocked by default), or have them double-click `build-clip.bat`, which pulls, renders and opens the clip. `node tools/build.mjs --gpu` is the underlying command.
- **They do not:** `node tools/build.mjs` renders in software. Warn them about the wait and start it in the background.
- **Only text or panels changed:** `node tools/build.mjs --hud` reuses the 3D frames and takes about a minute anywhere.

You cannot hear the result. Report loudness numbers if you measured them and say that the sound has not been listened to.

### 6. Deliver

Three things go to the user, not one:

1. **The clip** - `out/<name>.mp4`
2. **The cover image** - `out/cover.png`, made by the same build (or `node tools/render.mjs cover` alone, a few seconds). It is set up in `COVER` in the timeline. A cover has two jobs: make someone stop scrolling, and tell them exactly what they will learn. So: one huge result-word headline, a short line stating the promise with the number in it, the subject shown half outside / half inside, one tag per compared thing in its accent colour, and a strip saying how short the clip is. Keep all text inside the middle three quarters of the height, because profile grids crop covers to 3:4. Try a few camera angles with `QUERY="cam=az,el,d,tx,ty,tz&ct=seconds"` before settling.
3. **A caption for the post** - hook line, the 3-4 facts, call to action, hashtags, in the clip's language.

State what was simplified and what you could not verify.

For a new channel, also offer a **profile picture**: `node tools/render.mjs avatar` writes `out/avatar.png` (1080x1080, set up in `AVATAR` in the timeline). Keep it text-free and built from one bold shape - a close-up of the subject, half outside and half inside, inside a two-tone ring - because it is shown as a circle only a few dozen pixels wide. Check it cropped to a circle at 48 px before sending.

## Style rules

These came out of repeated rounds of feedback; breaking them is what made earlier versions get rejected. `references/style.md` gives the reasoning and the details.

- **Smooth, continuous forms.** The subject is one blended surface, not boxes, balls and tubes placed next to each other. Visible joins between primitives read as cheap.
- **Flat stepped shading**, no gradients, no dither noise, no texture. Every layer of the subject uses the same shading so the inside looks as finished as the outside.
- **The inside must fit inside.** Anything revealed under a surface has to be smaller than that surface in every pose. Check with an overlay.
- **Correct structure over decoration.** Parts attach where they really attach and have real proportions. Viewers who know the subject notice immediately.
- **Dark, quiet backdrop** with a stepped spotlight behind the subject and a pale rim on its silhouette, so the subject is the brightest, most saturated thing on screen.
- **Two or three accent colours** mapped to the two or three things being compared, used consistently in the subject, the labels and the charts.
- **Panels that feel alive**: values that move with the subject, a peak marker, a scrolling signal trace, a gauge, a summary chart - all fed by the timeline, never animated by hand.
- **Thai text** set in Kanit, drawn with hard pixel edges; captions type themselves; one-word callouts punch in at the key moment of each section.

## Files

- `references/brief.md` - what to collect from the user, with a filled example
- `references/architecture.md` - file map, the timeline's data structures, how to change each element
- `references/modeling.md` - building or changing the 3D subject
- `references/style.md` - the look, the panel effects, the sound, and why
- `assets/template/` - the complete working project to copy (clip, cover and build tools)
- `scripts/new-clip.mjs` - copies the template into a new folder
